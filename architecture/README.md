# 两套架构的分工与连接

这里的“两套架构”是用户提出的两份设计，并非两个现成软件产品。

| 架构 | 主要对象 | 输出 | 文档 |
| --- | --- | --- | --- |
| 人物属性历史 | 身份、关系、态度、能力、持物、身体、认知、目标的变化记录 | 某个故事时点／披露章节的角色卡 | [设计原文](01-character-history/设计原文.md) |
| 世界状态与事件因果 | 整个世界、持续过程、事件、前置条件、各方意图、效果和证据 | 全局状态、因果关系、角色认知、叙事披露四种视图 | [设计原文](02-world-events/设计原文.md) |

两者通过同一事件标识连接。人物属性变化保存触发事件和原文证据；世界事件的 effects 描述真实变化。角色历史可以是按人物读取事件后的投影，不需要另编一套人物剧情。

查询时分别限定故事时间、读者披露位置和角色获知时间。来源身份、确定性与采纳状态分开保存；角色自述不自动成为世界事实；新续写保持独立分支，未采纳稿不覆盖原作。

[此前 LightRAG 观察](此前LightRAG观察-引用.md)是用户提供的背景记录。[PLM、LightRAG、酒馆](../references/README.md)属于实现参考。这些设计与参考不构成“已经部署了完整小说自动机”的声明。

现有小样：[九个共享事件](../workbench/events/opening-v0.2.json)，对应[新开篇](../workbench/drafts/01-临时通知-v0.2.md)。它演示证据与状态记录，尚未实现通用数据库、角色卡查询API或反事实模拟器。
